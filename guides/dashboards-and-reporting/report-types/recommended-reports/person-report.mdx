# Overview

The Person report returns a list of people and can optionally include aggregated information about the events they completed. Each person appears once, even if they completed the same event multiple times in the period. For example, a person who converted twice in the time range shows up as a single row.

## How a Person Is Defined

The report returns the latest version of the person. If the person was updated after the events that identified them, the report returns the updated person.

## Rename and Reorder Columns

The **Mappings** section, in the **Advanced** menu, is where you set your column names, your values (the source of the data in each row), and your column order. To rename a column, replace the text in the first field. To reorder a column, use the up and down arrows.

## Predefined Mappings

The list of predefined mappings, below the mappings above, is a good starting point for pulling specific data from the person associated with the events (for example, the friend) or the related person (for example, the advocate).

Predefined mappings mean you don't need to know the syntax for a data attribute. For example, you can use the predefined Person ID mapping without knowing that the value for the `person_id` key is `event.person_id`. After you select a predefined mapping, reorder the columns with the up and down arrows to the left of the key field.

## Person and Related Person Mappings

Use the **Person** function to include attributes about the person (for example, the friend, `event.person_id`) or the related person (for example, the advocate, `event.related_person_id`). The Person function reads the profile of someone who completed an event — or someone related to them — and pulls information from it. You can also select these values with the **Predefined Mappings** button.

## Event Mappings

Use the **Event** function to include attributes about the person (the friend) or the related person (the advocate) at the time of the event. The Event function reads the event itself rather than the current profile.

## Sums

Use the **Sum** function to total the values of a data attribute across multiple events. For example, use it to see the total amount someone spent on `converted` events.

## Counts

Use the **Count** function to count the number of events a person completed in a time period. For example, use it to see the number of times someone had a `converted` event.

## Campaigns

Use the **Campaign** function to retrieve information about the campaign the person or related person participated in, such as the campaign name.

## Additional Settings and Filters

In the **Advanced** section, you can also set file formats, the delivery method, and event-specific filters. **Visit Type** defaults to New To Client.
