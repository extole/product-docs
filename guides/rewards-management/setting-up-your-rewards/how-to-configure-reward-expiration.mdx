# Overview

Reward expiration is the date and time after which a reward can no longer be redeemed. You can set expiration when you configure a reward, and you can set, change, or clear it on an issued reward from **View Reward**.

When a reward expires, it moves to **Expired** and cannot be redeemed. Expired Reward Bank collectibles are hidden from the Redemption Center.

<Info>
Expiration you set on a reward in Flow Builder is used instead of expiration set on the reward supplier, or on the Reward Bank Collectible Reward.
Changing reward expiration related settings does not update rewards that have already been earned.
To change the date on an issued reward, use **View Reward**.
</Info>

# When to Use Reward Expiration

Expiration changes the reward's state in Extole. It does not reach into a partner's system or your own, so it is most useful for rewards whose value is held in Extole.

| Reward type | Use expiration? | Where to set it | What happens when it expires |
| :--- | :--- | :--- | :--- |
| Reward Bank collectible | Yes, this is the main use | The Collectible Reward, or the reward in Flow Builder for one campaign | The reward leaves the Redemption Center and the balance, and can't be redeemed |
| Coupon | Optional | Usually nothing: the coupon's own expiration date is used | The reward shows as **Expired** in **User Support**. The code itself is controlled by your commerce platform |
| Tango gift card | No | — | The reward shows as **Expired** in Extole, but the card stays valid at Tango |
| Tremendous or BHN reward | Not supported | — | These rewards can't move to **Expired** |
| Account credit or other custom reward | Optional | The reward supplier, or the reward in Flow Builder | The reward shows as **Expired** in Extole. Your system is not told automatically |

## Reward Bank Collectibles

Set **Expires After** or **Expiration Date** on the Collectible Reward, so every collectible it issues follows the same rule. **Expires After** suits a policy such as "points last one year from when they're earned." Set expiration on the reward in Flow Builder only when one campaign needs a different rule.

Extole checks for rewards past their expiration date about once an hour. When a collectible expires:

- It no longer appears in the participant's Redemption Center, and its value is removed from their balance. The participant doesn't see it marked as expired. It is no longer listed.
- It can't be redeemed.
- **View Reward** in **User Support** shows its state as **Expired**, so your support team can explain where it went.

Collectibles that have already been redeemed don't expire. For how expiration works with points and balances, see [Points and Balances](/technical/platform-integrations/extensions/reward-bank/points-and-balances).

## Coupons

When your coupons carry an expiration date, or the coupon reward supplier has a **Default Expiration Date**, Extole uses that date as the reward's expiration when it issues the code. The date then shows on **View Reward** and the reward moves to **Expired** after it.

Set **Reward Expiration** on the supplier, or expiration on the reward in Flow Builder, only to replace the coupon's date. Either one is used instead of the coupon's date.

Expiring the reward in Extole does not deactivate the code in your commerce platform. Set the code's own expiration there.

## Gift Cards

Tango gift cards can expire in Extole, but Extole does not cancel the card at Tango, so the participant can still use it. Tremendous and BHN rewards don't support expiration. For gift cards, rely on the card's own terms rather than reward expiration.

The exception is a gift card offered as a redemption option in the Reward Bank. There, set expiration on the collectible the participant earns, not on the gift card.

## Account Credit and Other Custom Rewards

Expiration marks the reward **Expired** in Extole. It does not remove the credit from your system, and reward webhooks don't send the **Expired** state. If your system must remove the credit when the reward expires, contact your Extole team to set up a notification when the reward moves to **Expired**.

# Configure Expiration on a Reward Supplier

Use this when the supplier is not part of a component. Any standalone supplier in **Rewards** can have a **Reward Expiration**.

1. Navigate to **Rewards**.
2. Open the reward supplier.
3. Under **Reward Details**, set **Reward Expiration** with the date picker.

<Frame>
  <img
    src="/images/extole/reward-expiration-supplier.png"
    alt="Reward Details on a custom reward supplier, with Reward Expiration set to July 9, 2027 at 8:30 AM CDT."
  />
</Frame>

4. Save the supplier.

Every reward earned from this supplier uses that date, unless the campaign reward sets its own expiration.

# Configure Expiration on a Reward Bank Collectible Reward

They use **Expires After** and **Expiration Date** instead of **Reward Expiration**.

1. Navigate to **Rewards**.
2. Open the Collectible Reward.
3. Set **Expires After** (click **Add Custom Delay**) or **Expiration Date**. Use one of these settings, not both.

<Frame>
  <img
    src="/images/extole/reward-expiration-collectible.png"
    alt="Collectible Reward settings showing Expires After with Add Custom Delay, and Expiration Date with a date and time picker."
  />
</Frame>

4. Save the Collectible Reward.

**Expires After** counts from when the participant earns the reward. **Expiration Date** is a specific date and time.

# Configure Expiration on a Reward in Flow Builder

Use this to expire rewards for one campaign reward. This setting is used instead of the supplier's **Reward Expiration**.

1. Go to the [Programs](https://my.extole.com/programs) page and click **Manage Flow** for the campaign, or from the **Campaign Editor** select the **Flow** tab.
2. Click the reward to open its settings.
3. Set **Expires After** (click **Add Custom Delay**) or **Expiration Date**. Use one of these settings, not both.

<Frame>
  <img
    src="/images/extole/reward-expiration-reward-component.png"
    alt="Friend Reward on Signed Up settings showing Expires After with Add Custom Delay, and Expiration Date with a date and time picker."
  />
</Frame>

4. Click **Apply**.
5. Publish the campaign.

# View and Manage Expiration on a Reward

Open an issued reward to see whether it expires, change that date, or expire it now.

1. Click **User Support** in the sidebar and search for the person.
2. Open the person's profile and scroll to **Rewards**.
3. Click the reward to open **View Reward**.

If the reward has an expiration date, **View Reward** shows it under the current state as **Expires:**.

<Frame>
  <img
    src="/images/extole/reward-expiration-view-reward-expires.png"
    alt="View Reward showing a Sent reward with Expires set to September 29, 2026 at 11:11 AM CDT."
  />
</Frame>

When the reward has expired, the state is **Expired**.

  <img

  />
</Frame>

The header actions **Set Expiration Date**, **Clear Expiration Date**, and **Mark as Expired** may be disabled when they are not available for the reward's current state.

## Set or Change the Expiration Date

1. On **View Reward**, click **Set Expiration Date**.
2. Choose the **Expiration Date**.
3. Click **Set Expiration Date**.

<Frame>
  <img
    src="/images/extole/reward-expiration-set-date.png"
    alt="Set Expiration Date dialog with an Expiration Date field and a Set Expiration Date button."
  />
</Frame>

## Clear the Expiration Date

1. On **View Reward**, click **Clear Expiration Date**.
2. Confirm by clicking **Clear Expiration Date**.

<Frame>
  <img
    src="/images/extole/reward-expiration-clear-date.png"
    alt="Clear Expiration Date dialog asking to confirm clearing the reward's expiration date."
  />
</Frame>

## Mark a Reward as Expired

1. On **View Reward**, click **Mark as Expired**.
2. Optionally enter a note describing why you are expiring the reward.
3. Click **Mark as Expired**.

<Frame>
  <img
    src="/images/extole/reward-expiration-mark-as-expired.png"
    alt="Mark as Expired dialog stating that expired rewards cannot be redeemed, with an optional note and a Mark as Expired button."
  />
</Frame>

The reward moves to **Expired** and cannot be redeemed.
