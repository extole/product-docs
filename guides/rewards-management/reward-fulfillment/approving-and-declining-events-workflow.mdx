# Overview

As advocates and friends interact with your referral program, their actions generate events such as shares, clicks, registrations, account openings, quote submissions, purchases, and more. All events are scored for suspicious quality and are then either approved or declined based on suspicious event rules, automated workflows, file transfers, API calls, and manual intervention.

This article describes the most common options for managing your events, as well as the most common workflows.

# What Pending Means

**Pending** on a person's profile means one of two things: the event is still waiting to be approved, or the event was approved but no reward was created for it. They have distinct fixes, so check which one you're looking at first. An event still waiting to be approved is listed under **User Support** > **Approvals**. An approved event isn't.

## Waiting for Approval

An event that has been neither approved nor declined is **pending**. You'll see pending events on a person's profile and under **User Support** > **Approvals**.

The rewarding rules run when the event is approved, so a pending event has not earned a reward: there is no reward yet to fulfill, send, or wait on.

Two events can look identical on a profile and be pending for different reasons: one is waiting out an automatic transition you configured, and the other is waiting for a person who may never look at it. Check which of the two your campaign is set up for before you tell a participant their reward is on its way.

An event leaves pending one of two ways:

- **An automatic transition** approves the event types it is configured for, either immediately or after a delay you set. See **Automated Approval** below.
- **A person approves or declines it** under **User Support** > **Approvals**. Every event type with no automatic transition waits here, and waits indefinitely if nobody reviews it.

A campaign that configures an automatic transition for shares and no other event type leaves its registrations, clicks, and conversions pending however high their quality. Check that each event type you reward is covered by a transition, or that someone is reviewing it.

## Approved, but No Reward Was Created

A reward can also show **Pending** after its event was approved. The event passed every rule and earned the reward, but no reward was created, so there is nothing to show yet. Approving or transitioning the event again doesn't change that.

The usual reason is test traffic. An event in a test container, such as one from a site flagged as a test site, never earns the reward your campaign configures. It earns only a reward named **Default Test Reward**, and nothing at all when your account has no reward with that name. In that case, a successful test run shows every reward as **Pending**. To see an issued test reward, create a reward named **Default Test Reward** and run the test again. Rewards that are already **Pending** don't fill in by themselves. To test the rewards your campaign configures, use a site and a person that aren't flagged as test. See [Exclude Test Data from Analytics](/technical/operational-tasks/program-testing/exclude-test-data-from-analytics#rewards-for-test-events).

# Manual Approval

In this setup, you will go into the Extole platform and review all transactions that are either passing or suspicious and mark them as approved (rewarding the advocate if applicable) or declined (not rewarding the advocate if a reward is configured on the step). Manual approval follows this event workflow:

1. A new event enters the system.
2. Extole's quality engine reviews the event and marks it as passing or suspicious.

  1. Friend clicks marked as passing are automatically approved. Friend clicks marked as suspicious are automatically declined.

3. All transactions and transitions require an authorized user to approve or decline them.

In order to quickly approve and decline events, navigate to User Support --> Approvals from the sidebar.

![Screenshot showing In order to quickly approve and decline events, navigate to User Support --> Approvals from the sidebar.](/images/extole/859352e08ceca3211713aea270fe37b881bd297213c697d2da32a63e4017d53f.png)

In this view, quickly scan events to manually approve or decline in bulk. You can see the Person, who they were Referred By, the Campaign they participated in, the Date of the event in question, the Rule Results if it's a suspicious event, the Event Type, and the option to Approve or Decline.

# Automated Approval

To configure an automatic transition, navigate to the campaign you want to apply the automatic transition to and go to the Rules tab in the Campaign Editor. Under each event, click Advanced and configure your automatic transition settings.

Every event created in Extole appears in Event Live View in the User Support section of your My Extole account. Use the filters at the top of the table on the Event Live View page to only view the passing or suspicious events so you know which items require your attention.

![Screenshot showing Every event created in Extole appears in Event Live View in the User Support section of your My Extole account. Use the filters at the top of the table on...](/images/extole/f7d8ccd104d67c019987af8e6f2216293e7701a1bbedf0d3cfd151c7960807a6.png)

After determining whether or not an event is valid, select it and either Approve or Decline the event. Approval triggers any relevant rewarding rules and sends out the appropriate rewards.

# Frequently Asked Questions

## Are there other ways to configure workflows?

Yes. Extole has an extremely robust workflow system that can combine manual processes, RESTful APIs, batch files, etc. We recommend starting simple and determining if you want to reconfigure later on in your campaign.
