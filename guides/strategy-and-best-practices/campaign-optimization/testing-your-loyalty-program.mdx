# Overview

Loyalty programs are harder to test than referral campaigns, because the outcome you care about
happens weeks after the change. A member has to earn, accumulate, and redeem before a test tells
you anything.

This page covers what is worth testing, and how to run a test when the feedback loop is long. For
the mechanics of setting a test up, see
[A/B Testing Your Campaign](/guides/strategy-and-best-practices/campaign-optimization/a-b-testing-your-campaign)
and [A/B Testing Your Offer](/guides/strategy-and-best-practices/campaign-optimization/a-b-testing-your-offer).

# What to Test

## Program Structure

The highest-impact and slowest-reading tests.

* **Earn rate.** More points per action against fewer. Changes participation and cost together.
* **Redemption threshold.** A lower minimum redemption reaches a reward sooner; a higher one builds a bigger balance. Test which produces more redemptions overall, not just faster ones.
* **Banked against immediate.** Accumulating a balance against issuing a reward at the moment of action. These are different programs, and which wins depends on how often members interact with you.

## Rewards

Faster to read than structure, because a member chooses at the moment of redemption.

* **Reward mix.** Which Redemption Options members actually pick. Add an option and see whether it takes share or grows redemptions.
* **Reward value bands.** Whether members prefer a small reward now or save for a larger one.
* **Exclusive rewards against cash-equivalent ones.** Whether access and experiences pull as hard as gift cards.

## Ways to Earn

* **Which actions to reward.** Adding an earning action should increase the action. If participation does not move, you are paying for behavior you were getting anyway.
* **Reward behavior.** First Action against Every Action for a repeatable action.

## Messaging

The fastest-reading tests, and the ones to run while a structural test matures.

* **Earned reward emails.** Whether leading with the balance or with the reward drives more visits to the Redemption Center.
* **Reminders.** Whether prompting members with an unspent balance increases redemption.
* **Enrollment.** How the program is described at sign-up, and what that does to join rate.

# Running a Test

Set the test up by duplicating the campaign, changing one thing in the variant, and taking it live
as a test. Traffic splits 50/50, and existing participants continue in the campaign they are
already in.

<Warning>
  Because existing participants stay with the campaign they started in, a structural test reads
  against new members rather than your whole base. That is usually what you want — it avoids
  changing the deal for members mid-program — but it means the result describes new-member
  behavior, and it takes longer to reach a readable sample.
</Warning>

Compare the campaigns side by side on the
[Program Dashboard](/guides/platform-overview/program-and-campaign-dashboards).

# Reading a Result

Pick the measure before you start, and pick one that can actually move in the time you are prepared
to wait.

| Measure | Reads in | Tells you |
| :--- | :--- | :--- |
| Enrollment rate | Days | Whether the offer is attractive enough to join |
| Participation in earning actions | Weeks | Whether the earn structure changes behavior |
| Time to first redemption | Weeks to months | Whether the threshold is reachable |
| Redemption rate | Months | Whether points convert into something members want |
| Cost per member | Months | Whether the program is sustainable |

Do not read a structural test on an early measure alone. A variant that lifts enrollment and then
issues points nobody redeems has not won.

<Tip>
  Test messaging continuously and structure rarely. Message tests read in days and compound;
  structural tests are slow, expensive to reverse, and change what existing members were promised.
</Tip>

# Keeping Test Data Clean

Exclude your own testing activity from analytics, so internal redemptions do not distort a program
whose numbers are small early on. See
[Exclude Test Data from Analytics](/technical/operational-tasks/program-testing/exclude-test-data-from-analytics).
