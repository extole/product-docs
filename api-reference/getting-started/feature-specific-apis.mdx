The three platform APIs describe endpoints that are always present. A **feature specific API** describes the operations a single Extole feature exposes — reading a Reward Bank balance, force-approving a reward, sending one promotion email.

Read a feature's operations when you are integrating against that feature specifically. Read the platform APIs when you need events, persons, zones, or configuration.

## How These Differ

Three differences matter when you integrate.

**A feature has to be installed before its operations exist.** Features are installed into a program, so an operation is only available to you once the feature it belongs to is part of your campaign. If a call returns `404`, confirm the feature is installed before treating it as an error.

**A program can hold more than one of the same feature.** Two Reward Banks in one program each keep their own balances and their own transaction history, so a request has to identify which one it is addressing.

**The operations reuse the platform endpoints.** A feature operation is a documented, named use of an endpoint you may already be calling — several features submit to the events endpoint, each with its own payload. The operation tells you which payload that feature expects.

## Reading an Operation

Each operation lists its request and response schemas, its path parameters, the authentication it accepts, and the errors it returns — the same layout as the platform APIs. Operations are grouped per feature, and within a feature as:

| Group | What it does |
| --- | --- |
| **Views** | Reads state without changing it — a balance, a history, a status. |
| **Actions** | Changes state or causes work — a redemption, an approval, a send. |
