The three platform APIs describe endpoints that are always present. A **feature specific API** describes the operations a single Extole feature exposes — submitting a `purchased` event, rendering the `banner` zone.

Read a feature's operations when you are integrating against that feature specifically. Read the platform APIs when you need events, persons, zones, or configuration.

## How These Differ

Three differences matter when you integrate.

**A feature has to be installed before its operations exist.** Features are installed into a program, so an operation is only available to you once the feature it belongs to is part of your campaign. If a call returns `404`, confirm the feature is installed before treating it as an error.

**A program can hold more than one of the same feature.** Two onsite promotions in one program each render their own zone and keep their own configuration, so a request has to identify which one it is addressing.

**The operations reuse the platform endpoints.** A feature operation is a documented, named use of an endpoint you may already be calling. Every business event below is a `POST` to the events endpoint under its own name; every zone is a render of the zone endpoint under its own name. The operation tells you which name to use and what it carries.

## Reading an Operation

Each operation lists its request and response schemas, its path parameters, the authentication it accepts, and the errors it returns — the same layout as the platform APIs.

| Group | What it does |
| --- | --- |
| **Views** | Reads state without changing it — rendering a zone. |
| **Actions** | Changes state or causes work — submitting a business event. |

Business events are grouped further by the kind of journey they belong to — Account, Application, Booking, Ecommerce, Lead Flow, Loan, Policy, Ratings, Referral, Subscription, Sweepstakes, Workflow and others — because there are too many to read as one list.
