# Overview

[Configuration Concepts](/technical/configuring-extole/configuration-concepts) explains how to configure Extole through components, and it is all most readers need. This page describes the parts of a component. Use it when you build components of your own or troubleshoot one in depth.

A component has these parts:

| Part | What it is |
|---|---|
| Types | What kind of component it is. A component can have more than one type. |
| Settings | What you configure: values, the components placed inside it, and the components it uses. |
| Operations | The API calls the component offers to your site, app, or servers. |
| Elements | The parts that carry out its behavior at runtime. You don't see them when you configure a component. The component manages them. |

Types, settings, and operations are the component's interface. Elements are its implementation.

## Component Types

A component's types say what it is. [Get a component](/api-reference/components/get-a-component) returns them in `types`, and [List components](/api-reference/components/list-components) filters on them. To learn which kinds of component an account holds, list its components and read their types.

A component can have more than one type.

A type name carries a generation suffix, such as `business-event-v10.0`. The pages on this site drop the suffix when they name a type in prose.

A type can have a parent type. `reward-send-action-v10.0` is a kind of `action-v10.0`, and a setting that accepts the parent type accepts each type beneath it.

Three types mark the components that [Configuration Concepts](/technical/configuring-extole/configuration-concepts#the-components-you-start-from) starts from: `campaign-v10.0` for a campaign, `integration-v10.0` for an integration, and `extension-v10.0` for an extension. The components inside them have types such as `role-v10.0`, `journey-v10.0`, `business-event-v10.0`, `rule-v10.0`, `action-v10.0`, `content-v10.0`, and `reward-v10.0`.

## Settings

[List component settings](/api-reference/components/list-component-settings) returns a component's settings. Each setting has a name, a display name, a description, and a type. There are three kinds.

### Variables

A variable holds a value. Its type says what kind, such as `STRING`, `COLOR`, `BOOLEAN`, or `TRIGGER_CONFIGURATION`, and its values can differ by locale.

A variable's value can be an expression. [From Configuration to Runtime](/technical/configuring-extole/configuration-concepts#from-configuration-to-runtime) explains when an expression is worked out.

### Sockets

A socket holds other components. A `SOCKET` holds one, and a `MULTI_SOCKET` holds many. Each socket says which component types it accepts.

You fill a socket by copying a component into it. [List duplicatable components](/api-reference/components/list-duplicatable-components) with `target_component_id` and `target_setting_name` returns the components that fit a socket, and [Add component to setting](/api-reference/components/add-component-to-setting) installs a copy. The copy keeps the values of its source until you set your own.

Sockets make a tree: a component, the components in its sockets, and the components in theirs. The tree depends on which components are installed, so read it from the API. [List components](/api-reference/components/list-components) with `parent_component_id` returns the components beneath a component, `max_depth` sets how many levels to return, and `parent_socket_name` limits the first level to one socket.

### References

A reference points at something the component uses and does not hold.

A `COMPONENT_REFERENCE` points at one other component, and a `COMPONENT_REFERENCE_LIST` at several. [List selectable components for a component reference](/api-reference/components/list-selectable-components-for-a-component-reference) returns the components a reference accepts, and [Select a component for a component reference](/api-reference/components/select-a-component-for-a-component-reference) sets it.

Other setting types name one kind of thing: `REWARD_SUPPLIER_ID` a reward supplier, `AUDIENCE_ID` an audience, and `WEBHOOK_ID` a webhook.

## Operations

An operation is an API call that a component offers, such as an event your servers send to it. Each operation has a name, a description, a path, a method, and the schema of its request and response, so a component documents its own API in the same way it documents its settings.

[List component operations](/api-reference/components-operations/list-component-operations) returns the operations of a component.

## Elements

Elements carry out a component's behavior at runtime. They include the steps that record what a person did, the triggers that decide whether a step applies to an event, and the actions a step runs.

A component manages its elements. Its settings supply the values the elements use, which is how a setting changes behavior without a change to an element.

Elements are also what an upgrade replaces. [Upgrade a component](/api-reference/components/upgrade-a-component) keeps what you configured and takes the elements from the new version. [Configure Before You Modify](/technical/configuring-extole/configuration-concepts#configure-before-you-modify) explains what that means for a change you make to an element.
