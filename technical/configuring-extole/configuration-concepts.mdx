# Overview

Everything you configure in Extole is a **component**. A campaign is a component, and so is an integration, a reward, or a rule.

Every component works the same way. It has a name and a description that say what it does, one or more **types** that say what kind of component it is, and **settings** that you change to fit your program. When you know how to work with one component, you know how to work with all of them.

## Components Inside Components

You configure a component largely by choosing the components inside it. A campaign shows the shape:

```
Campaign
└── Role
    ├── Journey
    │   └── Business event
    │       ├── Rules
    │       ├── Actions
    │       └── Experiences
    └── Reward
```

A role is a kind of participant, such as advocate or friend. Each component in the hierarchy has components of its own. A reward is a rich example:

```
Reward
├── Trigger rules
├── Reward rules
└── Reward issuer
    ├── Send actions
    │   └── Reward email
    └── Fulfillment actions
```

These hierarchies show the common kinds. There are many more, and the components your account has depend on what you add.

A component holds its own copy of each component inside it. A change to a business event in one campaign reaches that campaign and no other.

## Components That Reference Other Components

A setting can also point at a component that lives elsewhere in the account. That component is set up once, and every component that references it sees the same one. Examples include:

- **Trigger events.** An integration or an extension provides the events an external system can send, and a business event chooses one of them as its trigger. See [How to Set Up Triggered By](/guides/flow-campaigns/how-to-set-up-triggered-by).
- **Reward suppliers.** A reward chooses the reward supplier that fulfills it.
- **Audiences.** A campaign chooses the audiences it targets.
- **Webhooks.** An action chooses the webhook it calls.

One reward supplier can serve many campaigns, and a change to it reaches all of them.

## Working with Components

You work with every component in four steps:

1. **Find the component.** Look at what your account has, or at what you can add to it. A component's types tell you what kind of component it is and where it fits.
2. **Read what it says about itself.** A component has a description, and so does each of its settings. The description is the documentation for that component.
3. **Configure its settings.** Set a value, choose a component to place inside it, or choose a component for it to reference.
4. **Validate the result.** Preview the change or test it in a draft before you publish.

You can take these steps in three places:

| Where | Use it for |
|---|---|
| **Extole Chat** | Most work. Ask in plain language what a component does, how it is set up, or for a change to it. See [Extole Chat](/product/extole-chat/index). [Extole AI Tools](/technical/extole-ai-tools/index) gives the same reach from an AI client you already use. |
| **My Extole** | Campaigns and programs are on the [Programs](https://my.extole.com/programs) page. Integrations and extensions are on the [Partners](https://my.extole.com/partners) page. Account-level settings are on the [My Account](https://my.extole.com/account-settings) page: set a value there once, and every program and campaign uses it. Reward suppliers are on the [Rewards](https://my.extole.com/account-rewards) page, and reports are on the [Reports](https://my.extole.com/reports) page. |
| **Management API** | Automation and your own tools. The [Components](/api-reference/components/list-components) endpoints find, read, and configure components. [Component Settings Over REST](/technical/platform-integrations/rest-apis/component-settings-over-rest) walks through a change. |

All three work with the same components, so a change you make in one appears in the others.

### Configure Before You Modify

Most components in your account are copies of components that Extole maintains. When Extole improves one, you can upgrade your copy, and the upgrade keeps everything you configured.

That is true only of configuration. A component does its work through parts beneath its settings, and it is possible to change those parts directly. An upgrade replaces them, so a direct change must be made again after each upgrade.

Configure a component through its settings. When a component has no setting for the behavior you need, look for another component that offers it. Modify what lies beneath a component as a last resort.

## From Configuration to Runtime

A component exists in three forms.

```
Component  ──►  Built component  ──►  Runtime component
```

| Form | What it is |
|---|---|
| **Component** | What you configure. A setting can hold a fixed value or an expression that works the value out. |
| **Built component** | What Extole makes of the component each time you save. Most settings now have their final values. |
| **Runtime component** | The built component at work. It responds to events, and it works out the few values that depend on the event or the person. |

### Build

Extole builds a component each time you save it. The build works out every value that configuration alone can decide:

- A fixed value stays as it is.
- A setting you have not changed takes the value of the component it was copied from.
- An expression that depends on other settings is worked out, and the built component holds the result.

The component answers "what did I set?" The built component answers "what will run?" When the two differ, the built component is the one to trust.

A build also checks the component. When a value cannot be worked out, the build reports it, so you learn of the problem when you save and not when a participant arrives.

### Runtime

At runtime, the built component responds to events. The same built component serves every person, and it works out the remaining values for each one.

A greeting that includes a person's first name shows the difference. The component holds the expression. The built component still holds it, because no person is known yet. The runtime component works it out for each person who arrives.

Nothing changes at runtime until you change the configuration. A change becomes a new built component, and your participants reach it when you publish.

### Which Form to Look At

| Question | Look at |
|---|---|
| What did I set? | The component and its settings. |
| What value will Extole use? | The built component. |
| What happened for one person or one event? | The runtime: the person's profile, with its events, steps, and rewards. |

## What Components Do at Runtime

At runtime, Extole works with events and people, and your components decide what happens to each event.

1. An **event** arrives from your site, your app, your servers, a file, or an integration. Extole finds or creates the **profile** of the person it belongs to.
2. **Targeting** finds the **business events** this event can start and chooses the campaign that applies to this person. Your audiences and **rules** decide which campaign that is and whether the event qualifies.
3. Extole records the business event as a **step** in the person's **journey**.
4. The business event's **actions** run: show an experience, send an email, call a webhook, or earn a **reward**.

The profile now holds the step and the reward, and they shape what the person is eligible for on the next event. [Key Concepts](/technical/integration-overview/key-concepts) describes each of these in more depth.
