---
title: "Event Dated Before the Referral Is Unattributed"
description: "Why an uploaded event can reach a referred friend and still be recorded unattributed when the time it carries is earlier than the friend's referral."
---

# Overview

An event reaches the right person and is saved, but it is recorded unattributed, and no reward follows. The person was referred, and the referral is valid. Other events for the same person, sent in the same file, may even have been attributed. This page covers one cause: the event carries a time from before the person's referral existed.

## Why the Event Time Matters

Extole attributes an event using the time the event carries, not the time it arrived. In a direct file upload, that time comes from the `event_time` column. If the column is empty, Extole uses the time the row is processed. See [File-Based Events](/technical/platform-integrations/files/file-based-events).

So an event can arrive weeks after the date it carries. A file that sends a qualification on the day it is earned, but dates it to the day the account opened, does this on every row.

When an event's time differs from the time it arrived, Extole ignores each referral and each journey created at or after that time. If the friend's referral was created later than the event time, the event is treated as having happened before the friend was referred, and it is recorded unattributed.

On a direct file upload, a date with no time of day resolves to the start of that day in your account's time zone. That makes this cause likely: a row dated to the start of the day is earlier than a referral made later that same day.

A Flow Builder file integration can change the event time before this check. Its **Delayed Event**, installed by default, removes `event_time` from the rows it matches and sends them at a new time, or skips them. See [Delay a File Event](/technical/platform-integrations/extensions/file-integration#delay-a-file-event).

## Why Another Event Can Still Attribute

A business event with an eligibility window holds each event for the length of the window, 24 hours by default, and then sends it again. Extole does not treat the resent event as dated in the past, so it is attributed if the referral exists by the time the window ends, whatever date the event carries.

A business event without an eligibility window does not do this. So the same person's account opening, with the same date, can be attributed while their qualification is not. An attributed event for the same person does not rule this cause out. Check which business events in the campaign have an eligibility window.

## How to Confirm It

For each unattributed event, compare two times:

1. The event time recorded for the event.
2. The time the friend's referral was created.

If the event time is earlier in every unattributed case, and later in the attributed cases, this is the cause.

## What to Do

The file's sender can fix it: send the actual time of the event in `event_time`. If only the date is known, send the end of that day, `23:59:59`, rather than its start.
