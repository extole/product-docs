title: "Campaign Renders for Some People but Not Others"
description: "Two campaigns in one program that share a journey name exclude each other, because targeting allows one live journey per program and keys that rule on the journey name."
---

# Overview

An integration or extension campaign renders for some people and not for others, with no pattern you can see, and you have several live campaigns in one program. It looks like an A/B test or an audience filter. It is usually neither.

## The Distinction That Matters

Targeting allows **one live journey per program**, so that variants of the same experience cannot both be selected for one person. That rule is keyed on the **journey name**, not only on the program label.

So two campaigns that are genuinely distinct integrations, but that share a program label **and** a journey name, are treated as the same journey. A person who already picked up that journey from the first campaign is not a candidate for the second, and the second one never renders for them.

This is why it looks intermittent. It fails only for the people who already have the sibling journey; everyone else renders normally. It is also why an apparently identical account is unaffected — if its two campaigns use distinct journey names, the rule never collides.

## Evidence That Settles It

- The person for whom the campaign did not render already has a journey from the same program.
- The two campaigns share both a program label and a journey name.
- An account running the same shape of setup with **distinct** journey names does not have the problem.

## What to Do

Give each campaign a journey name specific to its integration — prefixing the integration name is enough. Because the exclusion keys on the journey name, distinct names end the collision without restructuring anything else.

<Warning>
Program labels cannot be edited in place. Separating the campaigns into distinct programs means duplicating a campaign into a new program label and archiving the original, which is a much larger change than renaming a journey. Prefer distinct journey names.
</Warning>

If you run more than one live campaign in a single program, it is worth checking their journey names now rather than after someone reports a campaign that renders inconsistently.

## Not an A/B Test Problem

If a campaign is excluded because a journey from its program is already present, the cause is the journey rule. Audience membership, target filters and A/B allocation are all working as configured; changing them does not help and makes the setup harder to reason about.
