## Overview

Extole Offers connects your Stripe account to your Extole programs. Stripe sends events such as a successful payment, a subscription change, or a paid invoice to Extole. Extole identifies the person, evaluates your campaign, and — when a reward is earned — calls the Stripe API to issue it as a native Stripe object on that customer's account. No separate payout system is required.

You can issue a credit on the customer's Stripe balance, a promotion code redeemable against a Stripe coupon, or both.

## Prerequisites

| Requirement | Description |
| --- | --- |
| Stripe account | An active Stripe account. Complete setup in test mode before you switch to live keys. |
| Stripe API key | A secret key (`sk_test_...` / `sk_live_...`) or a restricted key, stored as an Extole Client Key. Grant it permission to read and write customers, read coupons, and write promotion codes, matching the rewards you will issue. |
| Stripe coupon | For Promotion Code rewards, create the coupon in Stripe first. Extole reads the coupon list live from the connected Stripe account. |
| Extole access token | A server-side token from the [Security Center](https://my.extole.com/security-center) with permission to post events. Do not use a token that can also manage campaigns. Stripe stores this token on the webhook endpoint. |

## Available Products

### Customer Balance

Issues a reward as a credit on the customer's Stripe balance. You configure a face value and currency. The credit amount is negative on the Stripe balance transaction, which reduces what the customer owes on their next invoice.

### Promotion Code

Issues a reward as a Stripe promotion code, redeemable against a coupon you created in Stripe. You configure a face value (for display), select the coupon from the connected Stripe account, and can optionally restrict redemption to the customer's first transaction.

## How Identity Works

When a Stripe event arrives, Extole takes the Stripe customer ID from the event and stores it as `partner_user_id`. Email, when present, is a secondary identifier.

Rewards are issued to that Stripe customer. If the person being rewarded did not arrive on a Stripe event — for example, an advocate whose friend converted in another system — the integration looks up a Stripe customer by the person's email and stores the matching customer ID.

The lookup succeeds when Stripe has one customer for that email. If Stripe has none, or more than one, Extole cannot issue the reward until the person has a Stripe customer ID.

## Integration

### Step 1: Add Extole Offers

1. In My Extole, go to **Partners**.
2. Add **Extole Offers (Stripe)**.
3. If it is not listed, contact [support@extole.com](mailto:support@extole.com) to have it added to your account.

### Step 2: Store Your Stripe Key

1. In Stripe, create a secret key or a restricted key. For a first setup, create the key in test mode.
2. In My Extole, go to **Security Center** > **Keys** and click **+ New Key**.
3. Set Type to **Webhook** and Algorithm to **Password**, and paste the Stripe key as the value.
4. Open **Extole Offers (Stripe)**, go to the **Configuration** tab, and set **Stripe Secret Key** to that Client Key.

<img src="/images/extole/1677caf608494119b4ad5b1ec8ed3016598dbbefd1f218fc032a60efb214fb00.png" alt="Create a Client Key in the My Extole Security Center" />

### Step 3: Send Stripe Events to Extole

1. In the [Security Center](https://my.extole.com/security-center), create an access token with permission to post events. Copy it once; you will not be able to view it again.

<img src="/images/extole/1099e785cae5de9d5347cbfb57fa8d90a706156b7a877a4c38d882419be8b3f8.png" alt="Click + New Access Token in the Extole Security Center" />

2. In the Stripe Dashboard, go to **Developers** > **Webhooks** and add an endpoint:

   ```text
   https://api.extole.io/v6/events/stripe_event?access_token=<access token>
   ```

3. Select these events:
   - `payment_intent.succeeded`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `invoice.paid`

If your program uses other subscription lifecycle events, work with your Extole team to add them. See [Stripe's webhook docs](https://docs.stripe.com/webhooks) for endpoint setup in the Stripe Dashboard.

### Step 4: Configure Rewards

1. Create any Promotion Code coupons in Stripe before you continue. They do not appear in Extole until they exist in the connected Stripe account.
2. In the integration's **Rewards** tab, add **Customer Balance**, **Promotion Code**, or both.
3. For Customer Balance, set the face value and currency.
4. For Promotion Code, select a Stripe coupon, set the face value, and optionally restrict redemption to the customer's first transaction.
5. In the [Flow Builder](/guides/flow-campaigns), open the reward on the event that should issue it and select the Stripe reward supplier.

## Test in Stripe Test Mode

1. Point the webhook and the Client Key at Stripe test mode.
2. Send a test event from the Stripe Dashboard, or complete a test payment.
3. In My Extole, confirm the event appears on the person's profile.
4. Confirm the reward in Stripe: a customer balance transaction, or a promotion code on the customer.
5. Switch the Client Key and the webhook to live keys only after that check passes.

## Partner to Extole Event Mapping

The following fields are extracted from each arriving Stripe event onto the corresponding Extole event:

| Field | Source |
| --- | --- |
| `partner_user_id` | `stripeObject.customer` |
| `amount` | `stripeObject.amount` |
| `currency` | `stripeObject.currency` |
| `status` | `stripeObject.status` |
| `email` | `stripeObject.customer_email` |
| `subscription` | `stripeObject.id` if the object is a subscription, else `stripeObject.subscription` |
| `previous_status` | `stripeEvent.data.previous_attributes.status`, present only on `.updated` events |

Field presence depends on the Stripe object type.

## Reward Fulfillment

When a reward is earned, Extole calls Stripe:

| Mechanism | Stripe API call |
| --- | --- |
| Customer Balance | `POST /v1/customers/{customer_id}/balance_transactions` |
| Promotion Code | `POST /v1/promotion_codes` |

Both calls include `metadata[extole_reward_id]` (the Extole reward ID) on the created Stripe object. Extole lists coupons with `GET /v1/coupons` when you configure a Promotion Code reward.

## FAQs

### Does the person need a Stripe customer before they can receive a reward?

Yes. Rewards are issued to a Stripe customer. If the triggering event includes a Stripe customer ID, Extole uses that. Otherwise the integration looks up a customer by email. There must be a Stripe customer to credit or to attach the promotion code to.

### What happens if the Stripe key is invalid or missing when a reward is earned?

The Stripe API call fails, and Extole marks the reward as failed.

### What if Stripe has no customer, or more than one, for the person's email?

The email lookup cannot choose a customer. Fulfillment fails until the person has a Stripe customer ID on their Extole profile.

### Can I use a restricted Stripe key instead of a secret key?

Yes. A restricted key is the better default. Grant it permission to read and write customers for Customer Balance rewards, and to read coupons and write promotion codes for Promotion Code rewards.

### Which token should I put on the Stripe webhook?

A normal access token with permission to post events, created in the Security Center. Do not use a superuser token or a token that can manage campaigns.
