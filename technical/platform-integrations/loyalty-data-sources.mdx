## Overview

[//]: # "How do loyalty events get into Extole from my other systems?"

A loyalty program earns on actions, and those actions happen across systems Extole does not own. A
purchase happens in a commerce platform or at a register, a review in a reviews platform, an
appointment in a scheduling system. Each one has to reach Extole as an event before it can earn
points.

This page maps each kind of source system to its integration path. For what an event becomes once
it arrives, see
[Points and Balances](/technical/platform-integrations/extensions/reward-bank/points-and-balances).

[//]: ___

## The Three Integration Paths

Every source resolves to one of three paths, in descending order of preference:

1. **A packaged integration.** Install and configure it. Extole maintains the mapping.
2. **The Events API.** Your system sends events directly. Use where no packaged integration exists
   and the event should arrive in real time. See
   [Sending Platform Events](/technical/building-custom-integrations/integration-types/sending-platform-events).
3. **File upload.** Batched events by SFTP or upload. Use for offline and back-office activity that
   does not need to be immediate. See
   [File-Based Events](/technical/platform-integrations/files/file-based-events).

## Point of Sale and In-Store

<Warning>
  There is no packaged point-of-sale integration. In-store earning is built with the Events API or
  file upload.
</Warning>

In-store purchases reach Extole when something ties the transaction to a person. In practice that
identifier is the member ID your loyalty program already issues, captured at the register and sent
with the transaction. Where in-store data settles in batches, a nightly file is usually the right
path; where you need points to appear before the member leaves the store, the transaction has to be
sent over the API.

This path covers earning — telling Extole that an in-store purchase happened so it can issue
points. Redeeming a balance at the register, or applying a discount inside a live transaction, is a
separate problem that depends on what your point-of-sale system allows. Discuss it with your Extole
team before designing around it.

For the strategy behind connecting in-store activity to a program, see
[Taking Referrals from Site to Store](/guides/strategy-and-best-practices/tactics-and-strategy/taking-referrals-from-site-to-store).

## Contact Center

<Warning>
  There is no packaged contact center integration.
</Warning>

Agents work with a loyalty program in two ways, and both are available without an integration:

* **Looking a member up.** User Support in My Extole shows a participant's profile, events, rewards, and the reasons a reward did or did not issue. See [Leveraging User Support Pages](/guides/platform-overview/leveraging-user-support-pages).
* **Correcting a balance.** An agent with the right permissions can create a missing event or issue a reward directly. See [Managing Member Points](/guides/rewards-management/reward-fulfillment/managing-member-points).

Where agents should stay in their own tooling, send the event from your contact center platform
over the Events API.

## Email and SMS Platforms

## Existing Loyalty Platforms

Where you already run a loyalty platform, Extole can credit points into it rather than banking them
itself. [SessionM](/technical/partners/loyalty/sessionm-loyalty-solution-guide) is a worked example
covering profile synchronization, a loyalty signup event, and a reward supplier that credits points
in the external system.

To build the same pattern against a platform with no packaged integration, see
[Build a Reward Fulfillment Integration](/technical/building-custom-integrations/integration-types/integration-build-reward-fulfillment).
