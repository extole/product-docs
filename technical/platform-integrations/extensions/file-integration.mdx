## Overview

File Integration is an extension that turns files delivered to your Extole directory into jobs that run on their own. Each job pairs the triggers that decide when a run starts with an ordered list of tasks to perform against every delivered file.

Use it for a recurring inbound CSV or SFTP feed — not a one-off [Batch Jobs](/technical/platform-integrations/files/general-file-uploads) upload, and not a custom inbound partner campaign.

| Goal | Use |
| :--- | :--- |
| Recurring inbound event files | This extension |
| A one-off CSV, PSV, or JSON upload | [General File Uploads](/technical/platform-integrations/files/general-file-uploads) |
| Create the Extole SFTP directory the files land in | [Extole SFTP Server](/technical/platform-integrations/files/extoles-sftp-server) |
| Connect an outside platform that posts events or webhooks | [Integration Categories](/technical/building-partner-integrations/integration-types/integration-categories) |

The column layout for event files is on [File-based Events](/technical/platform-integrations/files/file-based-events). This page covers installing the extension and configuring the job that already ships with it.

## Install File Integration

1. Open [Partners](https://my.extole.com/integrations) in My Extole.
2. Select the **Extensions** tab, then click **+ New Extension**.
3. Select **File Integration** and install it.

The installed extension has three tabs: **Overview**, **Configuration**, and **Job History**.

The install already includes an **Event File** job. Open **Configuration** and configure that job. Add another job only when you need a second pipeline.

If the account already has a live File Integration, configure that copy rather than installing a second one.

## Configure the Event File Job

On **Configuration**, the **Jobs** list shows **Event File**. That job processes every row of a matching file as a discrete event. It is enabled when the extension is installed.

Deliver files over [Extole SFTP](/technical/platform-integrations/files/extoles-sftp-server) into the directory you want processed. There is no source-connection picker on the extension — the job watches files that have already landed in your Extole directory.

### Triggers

**Event File** ships with one trigger:

- **File Name Matches**, setting **Filename Match Pattern**. The default is `.*\.csv$` (any CSV filename, JavaScript regular expression syntax — not glob syntax such as `*.csv`). Leave that pattern unless you have a naming convention to enforce. A guessed prefix silently drops every other CSV the job would have processed.

**Lands In Directory** is available to add. Its **Watch Directory** setting is the path prefix to watch (default `/incoming`). Add it when you need the job to ignore CSVs that land anywhere else. Both triggers must match for a file to run.

### Tasks

**Event File** ships with two tasks, in order:

1. **Validate Column Headers**
   - **Expected File Headers**: the column names a file must contain. The default is `email`. Replace that list with the header row you actually send.
   - **On Mismatch**: **FAIL** stops the run; **WARN** records a warning and continues. The default is **FAIL**. Headers must match as the same set in any order.
2. **Create Events**: one event per row of the validated file.
   - **Event Name**: the event that fires for every row. Leave it empty to take the event name from the file itself (the `event_name` column on [File-based Events](/technical/platform-integrations/files/file-based-events)).
   - **Trigger Events**: named events this job produces. A campaign business event, reward, or creative listens by selecting one. **Delayed Event** is installed here by default. See [Delay a File Event](#delay-a-file-event).

A sample header row is the contract for **Expected File Headers**. Do not invent columns the file does not contain.

**Update Audience** is a separate task you can add. It adds, removes, or replaces audience members from the delivered file. It is not on the default **Event File** job.

## Delay a File Event

**Delayed Event** holds a matching row and sends its event when that row's date arrives. Use it when the campaign should react on the row's date, not at the moment the file is processed.

A shipment date, an account-open date, or any other future date in the file is the usual case. Rows with no date, or a date that has already passed, can wait for a delay you set before the campaign sees them. Leave it unset when every row should fire as soon as the file is processed.

The add-on is installed on **Create Events**, under **Trigger Events**. **Enabled** is on, and **Event to Delay** is blank, so nothing is held until you set a name.

### How a Row Is Sent

Set **Event to Delay** to the **Event Name** on **Create Events**. If **Create Events** takes the name from the file, type that name here. A row with any other name is sent immediately.

| Row date | What happens |
| :--- | :--- |
| A future date and time | Sent at that time. **Delay** is ignored. |
| A time within the next minute | Sent immediately. |
| A date with no time | Sent that day, at the current time in your account, plus **Delay**. |
| No date, or a date that has already passed and is still inside **Lookback Window** | Waits for **Delay**, then sent. |
| Older than **Lookback Window**, or later than **Future Limit** | Sent immediately. A wrong year in the file does not sit for years. |
| A value that is not a date | Sent immediately. |

A time with no time zone uses your account time zone.

The event is sent with its original name and the row's columns. It does not reach the campaign at upload time. On the business event that should react, add the rule **Published event matches event names** next to the rule that already matches the input event.

One held event is pending per person and event name. Uploading the same file again is safe. A second future-dated row for that person and event is ignored until the first one is sent.

The hold follows the event name, not the job. Use a different name on each File Integration. Two integrations that name the same event both hold it, and the campaign can receive the event twice.

### Settings

| Setting | Default | What it does |
| :--- | :--- | :--- |
| **Enabled** | On | Turn off to send the event as soon as the file is processed. Saving the extension applies the change. |
| **Event to Delay** | Blank | Must match the **Event Name** on **Create Events**, or the name in the file. Leave blank to send every row immediately. |
| **Date Column** | `event_time` | Column that says when to send the event. If the file has an `event_date` column, that value is already stored as `event_time`. |
| **Delay** | 1 hour | How long to wait when the row has no date, or the date has already passed. A future date and time ignores this. A date with no time adds this delay. |
| **Only Events from Files** | On | Turn off to also delay this event when it arrives from the API, JavaScript, or a webhook. |
| **Lookback Window** | 365 days | How far in the past a date can be and still wait. Older dates send immediately. |
| **Future Limit** | 365 days | How far in the future a date can be and still wait. Later dates send immediately. |
| **Columns to Exclude** | Empty | Columns left off the event. Leave empty to include every column. |

## Watch Job History

Open **Job History** to see each run. A run shows the job name, time, file name, how many triggers and tasks ran, and status. Expand a run for the step-by-step trigger and task breakdown, including error text. Download the file from the run when you need the original.

Until a matching file has landed, the tab reads **No job history yet**.
