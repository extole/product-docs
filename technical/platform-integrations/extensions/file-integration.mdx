## Overview

File Integration is an extension that turns files delivered to your Extole directory into jobs that run on their own. Each job pairs the triggers that decide when a run starts with an ordered list of tasks to perform against every delivered file.

Use it for a recurring inbound CSV or SFTP feed — not a one-off [Batch Jobs](/technical/platform-integrations/files/general-file-uploads) upload, and not a custom inbound partner campaign.

| Goal | Use |
| :--- | :--- |
| Recurring inbound event files | This extension |
| A one-off CSV, PSV, or JSON upload | [General File Uploads](/technical/platform-integrations/files/general-file-uploads) |
| Create the Extole SFTP directory the files land in | [Extole SFTP Server](/technical/platform-integrations/files/extoles-sftp-server) |
| Connect an outside platform that posts events or webhooks | [Integration Categories](/technical/building-partner-integrations/integration-types/integration-categories) |

The column layout for event files is on [File-based Events](/technical/platform-integrations/files/file-based-events). This page covers installing the extension and configuring the job that already ships with it.

## Install File Integration

1. Open [Partners](https://my.extole.com/integrations) in My Extole.
2. Select the **Extensions** tab, then click **+ New Extension**.
3. Select **File Integration** and install it.

The installed extension has three tabs: **Overview**, **Configuration**, and **Job History**.

The install already includes an **Event File** job. Open **Configuration** and configure that job. Add another job only when you need a second pipeline.

If the account already has a live File Integration, configure that copy rather than installing a second one.

## Configure the Event File Job

On **Configuration**, the **Jobs** list shows **Event File**. That job processes every row of a matching file as a discrete event. It is enabled when the extension is installed. Turn **Enabled** off on the job to stop processing without deleting the job.

Deliver files over [Extole SFTP](/technical/platform-integrations/files/extoles-sftp-server) into the directory you want processed. There is no source-connection picker on the extension — the job watches files that have already landed in your Extole directory.

### Triggers

**Event File** ships with one trigger:

- **File Name Matches**
  - **Filename Match Pattern**: the default is `.*\.csv$` (any CSV filename, JavaScript regular expression syntax — not glob syntax such as `*.csv`). Leave that pattern unless you have a naming convention to enforce. A guessed prefix silently drops every other CSV the job would have processed.
  - **Watch Directory** (optional): an SFTP destination and folder. When set, the file must land under that directory on the selected destination. Leave it empty to match by filename alone.

**Lands In Directory** is available to add. Its **Watch Directory** setting is the SFTP destination and folder to watch. If the path is missing or empty, the job watches `/incoming`. Add it when you need the job to ignore files that land anywhere else. When both triggers are present, both must match for a file to run.

Each trigger has an **Enabled** setting. Turn a trigger off to ignore it without deleting it. A job whose triggers are all off does not run.

### Tasks

**Event File** ships with two tasks, in order:

1. **Validate Column Headers**
   - **Expected File Headers**: the column names a file must contain. The default is `email`. Replace that list with the header row you actually send.
   - **On Mismatch**: **FAIL** stops the run; **WARN** records a warning and continues. The default is **FAIL**. Headers must match as the same set in any order.
2. **Create Events**: one event per row of the validated file.
   - **Trigger Events**: the events this job's rows produce. Rename each component to the event name its rows use. Mark one as **Default Event** so every row uses that name; with none marked, the event name comes from the file (the `event_name` column on [File-based Events](/technical/platform-integrations/files/file-based-events)). A campaign business event, reward, or creative listens by selecting one of these under [Triggered By](/guides/flow-campaigns/how-to-set-up-triggered-by). The install ships **Delayed Event** only. For rows that should fire when the file is processed, add **Event**, rename it to the name campaigns should select, mark **Default Event** when every row should use that name, and leave **Event** enabled. Keep **Delayed Event** enabled only when rows should wait for a date. See [Delay a File Event](#delay-a-file-event).

A sample header row is the contract for **Expected File Headers**. Do not invent columns the file does not contain.

Each task has an **Enabled** setting. Turn a task off to skip it for every run without deleting it.

**Update Audience** is a separate task you can add. It adds, removes, or replaces audience members from the delivered file. It is not on the default **Event File** job.

## Delay a File Event

On **Create Events**, under **Trigger Events**, **Event** and **Delayed Event** name an event the file rows produce. Campaigns select that component under **Triggered By**. They differ in when the event is sent.

**Event** sends the event when the file is processed. Rename the component to the event name. Mark **Default Event** when every row should use that name. Use it when the campaign should react as soon as the file lands. Add it whenever processing is immediate — including when you turn **Delayed Event** off.

**Delayed Event** holds each matching row and sends the event when that row's date arrives. Rename the component to the event name those rows use. Mark **Default Event** when every row should use that name. Use it when the campaign should react on the row's date, not at the moment the file is processed. A shipment date, an account-open date, or any other future date in the file is the usual case. Rows with no date, or a date that has already passed, can wait for a delay you set before the campaign sees them.

**Delayed Event** is installed by default. **Enabled** is on. Until you rename it to the event name in the file (or set **Event to Delay**), it does not match any rows, so nothing is held.

### How a Row Is Sent

**Delayed Event** matches a row when the row's event name equals this trigger event's name (the component name by default). A row with any other name is sent immediately.

Timing uses the row's `event_time` column. If the file has an `event_date` column, that value is already stored as `event_time`.

| Row date | What happens |
| :--- | :--- |
| A future date and time | Sent at that time. **Delay** is ignored. |
| A time within the next minute | Sent immediately. |
| A date with no time | Sent that day, at the current time in your account, plus **Delay**. |
| No date, or a date that has already passed and is still inside **Lookback Window** | Waits for **Delay**, then sent. |
| Older than **Lookback Window**, or later than **Future Limit** | Not sent. A warning is raised, so a wrong year in the file does not sit for years. |
| A value that is not a date | Not sent. A warning is raised. |

A time with no time zone uses your account time zone.

The event is sent with its original name and the row's columns. It does not reach the campaign at upload time. In a campaign that uses **Triggered By**, select this **Delayed Event** in the business event's **Triggered By**; it matches the event when it is sent. In a campaign without **Triggered By**, add the rule **Published event matches event names** to the business event that should react, next to the rule that already matches the input event.

One held event is pending per person and event name. Uploading the same file again is safe. A second future-dated row for that person and event is ignored until the first one is sent.

The hold follows the event name, not the job. Use a different name on each File Integration. Two integrations that name the same event both hold it, and the campaign can receive the event twice.

### Settings

| Setting | Default | What it does |
| :--- | :--- | :--- |
| **Enabled** | On | Turn off to send the event as soon as the file is processed. Campaigns that already selected this **Delayed Event** under **Triggered By** still receive those immediate rows. Saving the extension applies the change. |
| **Default Event** | Off | When on, every row fires as this trigger event and uses this event's name. Only one trigger event per job can have this on. When off, the event name in the file is used. |
| **Event to Delay** | The component name | Must match this trigger event's name or the name in the file. Change the component name instead of typing a different value here. Use a unique name so events from another File Integration are not delayed. |
| **Delay** | 1 hour | How long to wait when the row has no date, or the date has already passed. A future date and time ignores this. A date with no time adds this delay. |
| **Only Events from Files** | On | Turn off to also delay this event when it arrives from the API, JavaScript, or a webhook. |
| **Lookback Window** | 365 days | How far in the past a date can be and still wait. Older dates are not sent, and a warning is raised. |
| **Future Limit** | 365 days | How far in the future a date can be and still wait. Later dates are not sent, and a warning is raised. |
| **Columns to Exclude** | Empty | Columns left off the event. Leave empty to include every column. |

## Watch Job History

Open **Job History** to see each run. A run shows the job name, time, file name, how many triggers and tasks ran, and status. Expand a run for the step-by-step trigger and task breakdown, including error text. Download the file from the run when you need the original.

Until a matching file has landed, the tab reads **No job history yet**.
