# Overview

Your account can use its own components and the components of the accounts it subscribes to, including the templates that Extole provides. [Configuration Concepts](/technical/configuring-extole/configuration-concepts) explains where those components come from.

To find a component, list them with [List duplicatable component summaries](/api-reference/components/list-duplicatable-component-summaries). It returns one short row for each component, and its page lists the fields of a row. When you have found a few candidates, read them in full to choose between them, with [Get a component](/api-reference/components/get-a-component), [List component settings](/api-reference/components/list-component-settings), and [List component operations](/api-reference/components-operations/list-component-operations).

## Filter by Type

A component's types say what kind of component it is, and so where it fits. [The Underlying Configuration Model](/technical/configuring-extole/underlying-configuration-model#component-types) explains types. To list the components of a type, pass it as `having_any_types`, which keeps a component that has at least one of the comma-separated types, or `having_all_types`, which keeps a component that has all of them.

## Find a Template

A template is a component that Extole provides for you to copy. The `owner` of a row says which account holds the component: `EXTOLE` for Extole's default template accounts, `EXTOLE_BETA` for Extole's component library and beta accounts, and `CLIENT` for any other account, your own included.

1. **List the components of the type you need, and set `show_all` to `true`.** `show_all` decides which components of a subscribed account the list holds. Without it, the list holds only the components of `LIVE` campaigns whose program type is `integration` or `campaign-component`. With `show_all` set to `true`, it holds them all.
2. **Keep the rows that Extole owns**, with the owner `EXTOLE` or `EXTOLE_BETA`.
3. **Choose by `display_name` and `description`.** The `name` parameter filters on the component's `name`: without `*` it must equal the whole name, and `*` at the start, the end, or both matches the end, the start, or any part of it. To match a display name, filter the rows in your own code.
4. **Copy it.** Send the row's `id` to [Duplicate a component](/api-reference/components/duplicate-a-component). In the request body, `target_campaign_id`, `target_component_absolute_name`, and `target_setting_name` say where the copy goes.

### Example: Campaign Templates

A campaign template is a template whose `types` include `campaign-v10.0`, the type of a Flow Builder campaign's root component. Its `name` is `root`, and its `display_name` is the template's name, such as `Refer a Friend`, `Welcome Offer`, `Reward for Action`, or `Custom Campaign Template`.

```bash
curl --get "$EXTOLE_API_HOST/v1/components/duplicatable/summaries" \
  --header "Authorization: Bearer $MANAGEMENT_API_ACCESS_TOKEN" \
  --data-urlencode "having_any_types=campaign-v10.0" \
  --data-urlencode "show_all=true"
```

A row from that list, trimmed to the fields this page uses:

```json
{
  "id": "7595588148547844495",
  "name": "root",
  "display_name": "Reward for Action",
  "types": ["campaign-v10.0"],
  "owner": "EXTOLE",
  "campaign_id": "7595588147951656208"
}
```

To copy the whole campaign, send the row's `campaign_id` to [Duplicate a campaign](/api-reference/campaigns/duplicate-a-campaign). The copy is a new draft campaign in your account, and the request body can set its `name` and its `program_label`:

```bash
curl --request POST "$EXTOLE_API_HOST/v2/campaigns/$CAMPAIGN_ID/duplicate" \
  --header "Authorization: Bearer $MANAGEMENT_API_ACCESS_TOKEN" \
  --header "Content-Type: application/json" \
  --data '{"name": "Spring Referral Program", "program_label": "your-program-label"}'
```

If no row has the owner `EXTOLE`, your account does not subscribe to Extole's templates. Contact your Customer Success Manager about the subscription, as [Your Team at Extole](/product/extole-overview/your-team) describes.

## Find a Component That Fits a Socket

A socket accepts components of certain types. To list only the components that fit a socket, add the component that holds the socket and the socket's name:

```bash
curl --get "$EXTOLE_API_HOST/v1/components/duplicatable/summaries" \
  --header "Authorization: Bearer $MANAGEMENT_API_ACCESS_TOKEN" \
  --data-urlencode "target_component_id=$COMPONENT_ID" \
  --data-urlencode "target_setting_name=$SOCKET_NAME"
```

Copy one into the socket with [Duplicate a component](/api-reference/components/duplicate-a-component), as in [Find a Template](#find-a-template).

## Walk a Component Tree

To list child components, pass the parent's id to [List components](/api-reference/components/list-components) as `parent_component_id`:

```bash
curl --get "$EXTOLE_API_HOST/v1/components" \
  --header "Authorization: Bearer $MANAGEMENT_API_ACCESS_TOKEN" \
  --data-urlencode "parent_component_id=$COMPONENT_ID" \
  --data-urlencode "max_depth=all"
```

`max_depth` is `1` by default, which returns the direct children. Set it to a number of levels, or to `all` for the whole subtree. Add `parent_socket_name` to start from the children in one socket. Each component in the response carries `component_ids` and `installed_into_socket`, which name its parent and the socket it sits in.

## Narrow a Long List

A library can hold thousands of components, and a list returns up to `limit` of them, 1000 by default, starting at `offset`. Filter before you page, by type, tag, name, or state; the operation's page in the API Reference lists every filter. To read every component, page as [Paging and Filtering List Endpoints](/technical/platform-integrations/rest-apis/paging-and-filtering-list-endpoints) describes.
