## Overview

[//]: # "What actions can customers earn loyalty points for?"

A way to earn is a business event paired with a reward rule. Ways to earn are configured inside a
**Reward for Action** program, which is the program type a loyalty program is built on.

Extole does not ship a fixed list of earning actions. Any action you can send to Extole as an event
can earn points, which means the catalog below is a starting point rather than a boundary.

Each way to earn needs three things: an event that tells Extole the action happened, a Collectible
Reward that defines how many points the action is worth, and reward rules that decide who qualifies
and how often. For the configuration steps, see
[How to Set Up a Loyalty Program](/guides/programs-and-campaigns/how-to-set-up-a-loyalty-program).

[//]: ___

## Transactional and Spend-Shaping

Actions tied directly to revenue. These are the most common place to start, because the event is
already flowing into Extole if you run any other program.

**Purchases**: Earn a set number of points per purchase, or a dynamic amount based on order value.
A dynamic Collectible Reward calculates points as a percentage of the transaction, with a minimum
and maximum you set.

**Points per dollar spent**: The dynamic reward configuration expressed as a rate. Ten points per
dollar is a dynamic reward with the rate set accordingly.

**Spend thresholds**: Reward a participant when cumulative or single-order spend crosses a value
you choose. The threshold is a reward rule condition on the event data, not a separate event.

**Category-specific purchases**: Reward more for a product category or line by adding a condition
on the event data to the reward rule, so only qualifying purchases earn.

**Upsell and cross-sell offers**: Reward the specific action you want to encourage, using the same
event-data conditions.

## Acquisition and Advocacy

Actions that bring new people in or deepen a participant's relationship with the brand.

**Joining the loyalty program**: Reward enrollment itself. This is often the first points a
participant ever sees, and it gives them a reason to complete the sign-up.

**Referrals**: A loyalty program can reward referrals alongside a Refer A Friend program. The
referral is a separate journey linking two people, and the points land in the same Reward Bank.

**Referral milestones**: Reward a participant on their second, third, or fifth successful referral
rather than every one. See
[How to Set Up Bonus Rewards on a Specific Referral Count](/guides/flow-campaigns/how-to-set-up-bonus-rewards-on-a-specific-referral-count-2nd-3rd-5th-etc).

**Account creation**: Reward a participant for opening an account, using the registration event you
already send.

**Profile completion**: Reward a participant for supplying data you want, such as preferences or a
birth date. Send the completion as an event and set the reward to issue on the first action only.

**Email or SMS signup**: Reward an opt-in. Confirm the opt-in is recorded in your own system of
record as well, since Extole rewards the event rather than managing the subscription.

**App download**: Reward a first app open or a first in-app session. The mobile SDKs can send this
event.

## Engagement and Feedback

Actions that show attention rather than spend. These usually carry smaller point values, which is
what the Reward Bank's micro-reward model is built for.

**Surveys and reviews**: Reward a participant for completing a survey or submitting a review.
Extole does not integrate with survey or review providers. The action happens in the platform you
already use, and that platform — or your own systems — sends Extole the event once it is complete,
by API, file upload, or the **Create Event** page.

**Product registration**: Reward a participant for registering a product they own. Where the
registration carries a purchase identifier, it can also connect an offline or retail purchase back
to the participant.

**Events and appointments**: Reward attendance or a completed booking. Appointment systems can send
this event; see [Boulevard (BLVD)](/technical/partners/appointment-management/boulevard-blvd) for a
worked example.

## Milestones and Occasions

Actions defined by time or count rather than by something the participant just did.

**Birthday and anniversary rewards**: Issue points on a date held on the participant's profile.

**Nth purchase milestones**: Reward the fifth or tenth purchase using a reward rule that counts
prior qualifying events.

**Tenure milestones**: Reward length of membership or subscription. The milestone is reached by
time rather than by an action, so your system sends the event when the participant qualifies.

## Custom Events

Anything else you can describe as an event can earn points. Define the business event, send it to
Extole by API, file upload, or an integration, and attach a Collectible Reward to it. See
[Where Events Come From](/technical/solutions/extole-solution-guides/loyalty#where-events-come-from) for how events arrive
from each kind of system.

<Tip>
  Start with two or three ways to earn that use events already flowing into Extole, then expand.
  Every additional earning action adds points liability, and a program with too many low-value ways
  to earn is harder for a participant to understand.
</Tip>

## How Often a Participant Earns

Each reward is configured with a reward behavior that controls repetition:

| Behavior | Effect |
| :--- | :--- |
| First Action | Points are issued only the first time the event occurs. Use for one-time actions such as enrollment, app download, or profile completion. |
| Every Action | Points are issued every time the event occurs. Use for purchases and repeatable engagement. |
| Every Unique Action | Points are issued once per unique value of a data parameter you specify. Use where an action repeats but should only earn once per item, such as one review per product. |
